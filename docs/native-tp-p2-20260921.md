# TP grouped MoE 实施记录

本项落实完整优化方案的 P2，仍为候选实现，未替换 30001 的原服务。

## 当前代码

- launcher 增加 `--tp-moe-prefill row|grouped`，默认 row；grouped 的算术策略进入
  manifest/runtime identity，避免不同算术路径复用 session。
- route planner 接受本卡 256 个专家及未归属的 `-1`，给未归属路由设置显式 sentinel。
  pack 跳过这些路由，避免读取无效输入；其他越界专家仍返回错误。
- grouped 输出先按原 token/top-k 顺序归并成 FP32 partial，再执行跨卡规约。
  不规约各卡排列不同的 expert-packed buffer。
- TP 在 down projection 后乘路由权重；PP 保留现有中间激活加权策略。
  这避免额外移动 BF16 舍入边界，但 grouped WMMA 与逐行点积的算术仍可能不同，
  不能据此宣称整模型逐位等价。

## 第一轮实权重对照

同候选二进制、W4/W8、RAM PLE、P2P、常驻 worker、异步 P2P，比较 row/grouped。
测试使用同一中文 chat token 序列的不同长度前缀，每个长度重复三次，随后各追加
相同 8 个 token 并采集完整 BF16 logits。没有把某一路生成的不同 token 回灌。
两种模式均开启 logits diagnostics，按 row→grouped 顺序执行；不是 SSE decode
吞吐或完整问答质量测试。表中为每个长度后两次 append RPC 耗时的中位数。

| 输入 token 数 | row ms | grouped ms | row/grouped |
|---|---:|---:|---:|
| 2 | 53.232 | 58.644 | 0.908× |
| 3 | 70.095 | 74.043 | 0.947× |
| 5 | 104.544 | 105.206 | 0.994× |
| 7 | 138.890 | 134.812 | 1.030× |
| 8 | 53.307 | 46.831 | 1.138× |
| 16 | 84.919 | 63.261 | 1.342× |
| 32 | 149.054 | 91.294 | 1.633× |

结果支持大 batch 的性能方向，但不能直接用于 MTP6：7 行只快约 3%，且 2/3 行
退化。7→8 行的跳变与 dense GEMM 的 M≥8 分支一致，需测正确 padding 的小 M
路径；不能直接修改阈值并假定所有 cuBLAS 布局均支持。

216 对完整 logits 均为有限值、top-1 相同，两模式各自三次重复均逐位一致；
但跨模式没有一份逐位相同。512-token case 的 append 最大绝对差 11.6445、
RMSE 1.25754，后续单行追加的最大绝对差达 12.6836。**数值验收未通过，不能推广。**
这不是已证明的 kernel bug，也不能未经定位就归因于正常舍入。

测试前缀多数落在未结束的 user 消息内部，216 次参考 top-1 中 207 次为 248046，
因此 top-1 一致的质量证明力很弱；必须补完整 chat、代码/数学及完整生成测试。
frontier 一致也不等于 GDN/PLE 状态字节相同。

## 逐层诊断与小 M padding

新增 `--tp-small-gemm`（默认关闭）：TP 的 2..7 行 dense 输入补零至 8 行，执行
GEMM 后仅拷回真实行。使用有界 scratch，计入矩阵缓存预算，sealed 后不扩容。
策略进入 runtime identity。CPU 矩阵乘法 oracle、M=2/3/5/7、K=128/320/640/2560、
N=17 非整齐维度、poisoned scratch 和输出 guard 的独立 CUDA 测试均通过。

候选 binary 位于远端 `source-small-gemm/build/q38-cuda-runtime`，SHA256 为

独立证据目录：`../.artifacts/q38-native-opt-p2-detail-20260921/`。

另行运行 grouped+逐层诊断：共 2,592 条（27 次多行输入×48 层×2 ranks），
同层同输入 partial 最大相对 L2 误差约 0.6493%。该模式输出的 216 份 logits 与
上一轮 grouped 全部逐位一致，说明诊断本身未扰动本批结果。不得把诊断耗时用于
加速比。局部算子误差和整模型误差不是同一量，也尚未证明差异全部来自舍入。

其余 M<8 最大绝对 logit 差 1.25；216 次 top-1 一致。三个模式各自重复确定，
完整数学/复述/代码提示均运行至 stop，输出 token 完全相同，分别为 391、蓝天白、
`def square(x): return x ** 2`。这只是小范围功能检查，不能替代整体质量与状态验收。

下一步优先分离 BF16 解量化舍入与 FP32 求和顺序的影响，评估逐 G128 group
Tensor Core 点积后以 FP32 应用 scale，避免把 quant×scale 先舍入为 BF16。
该精度改进的后续实现与实测见下文。全部候选继续保持 opt-in，原服务按旧命令恢复。

## FP32 quant-group scale 路径

新增 `--tp-moe-prefill grouped-fp32`。每个 G128 分组用精确可表示的整数 quant
参与 BF16 Tensor Core 点积，在 FP32 中乘原 scale 并累加，最后保留原 gate/up
和激活的 BF16 边界。避免先将 quant×scale 舍入成 BF16。独立特化保留旧路径，
支持 W4 row-major/tiled、W8；使用 WMMA row-major store 映射输出坐标。

CUDA 测试覆盖所有输出列、不同非 2 的幂次 scale、G128 的 0/63/127 位置、
有符号 W4/W8、W4 奇数 nibble 与两种布局，以 CPU FP32-group 算术为 oracle。
首轮及扩展测试均通过，runtime 编译成功；二进制 SHA256：
`9aba009d8b8d17d0d878f4635c11999c2b680f408f6a6b3c717ba66cbb8db4ea`。
证据目录 `../.artifacts/q38-native-opt-p2-fp32-20260921/`。

同二进制 row 对比 FP32 grouped+small，热态 prefill：7 行 138.723→54.930 ms
（2.525×），512 行 2.10722→0.70121 s（3.005×）。依然是 diagnostics 开启、
顺序三次、后两次中位数的短测，不是完整 MTP verify 或线上 decode 吞吐。

2,592 条同层同输入诊断的最大相对 L2 误差从旧 grouped 的 0.00649252 降至
0.000469031，但整模型 216 对 logits 仍没有逐位相同，最大绝对差 12.0664，
top-1 全相同。数学/复述/代码三例均到 stop，三个模式输出 token 一致。

额外统计 216 份前缀快照与 3 个完整提示首步的 softmax 分布（总 219 对）：
旧 grouped→FP32 grouped，KL 中位数约 3.566e-5→1.054e-5，最大 KL
0.01820→0.01050，最大 total variation 0.06892→0.05380。这些新指标解释
数值差异的影响，不替代原来的误差记录或质量门槛。最差位置仍有约 5.38 个百分点
的概率质量变化，且样本以截断 user 内容为主；完整质量/状态验收依然未完成。

局部误差下降未消除整模型差异，不能断言唯一根因或宣称已经等价。后续需要正常
回答位置的固定 token 序列、更多任务、状态对照，并继续推进多行目标 API。
