# 原生 TP 第一批调度优化实测

本轮属于[完整优化方案](native-tp-optimization-plan-20260921.md)的 P1：
新增可选的常驻 peer worker 和 stream-ordered P2P，保持原有算术、权重、SSD/RAM
选择和单事务协调器。尚未启用 TP Graph、MTP 或 grouped MoE。

## 改动

- `PairedRankWorker`：每 logical stage 复用一个 peer 线程，rank 0 保留在调用者
  线程上。每次调用等待两个 rank 完成，保存异常，并在失败时唤醒 collective peer。
  worker 先于其访问的 rank backend 析构；显式清空 moved-from `std::function`。
- `--tp-p2p-async`：两 rank 成对入队后 CPU 返回。GPU 依赖仍完整包含 producer
  ready、双方输入 read-done 和上一代输出完成；后一项保护跨 stream 的 scratch
  复用。扩容、transport 切换与 bridge reset 会排空尚未完成的 peer 工作。
- `--tp-persistent-worker`：launcher 显式设置 `Q38_TP_PERSISTENT_WORKER=1`；关闭
  时保持原来的线程路径。两个新开关默认关闭，异步通信要求 P2P。
- CPU 发布与后续读取仍遵循 stream 完成边界；未将 GPU 尚未完成的 token 提前发布。

## 同二进制四组对照

机器为 hp-z4-server 双 CMP 170HX，现有 W4/W8、RAM PLE、P2P、单请求 greedy。
使用 direct RPC，web/thinking 输出预算 256，web 重复三次；每次 reset 后重新 append。
为了同时比较整模型数值，四组均开启 raw-logit diagnostics。计时为 decode RPC
调用数/这些调用的耗时和，排除 seed 和额外拉取 logits 的 RPC 时间。

| 开关 | web 三轮平均 tok/s | 相对同步基线 | thinking tok/s |
|---|---:|---:|---:|
| 同步 P2P、临时线程 | 32.756 | 1.000× | 32.663 |
| 仅常驻 worker | 33.095 | 1.010× | 33.150 |
| 仅异步 P2P | 36.333 | 1.109× | 35.750 |
| 常驻 worker＋异步 P2P | **36.990** | **1.129×** | **36.695** |

组合模式 web 的三次结果为 36.666 / 37.126 / 37.177 tok/s。排除第一轮后的两轮
均值为 37.151，基线相同口径为 32.763。较长输入样本的 prefill 耗时 1.471→1.469 秒，
没有有意义的改善；本轮没有改动 TP MoE 的逐 token prefill。

这是短序列、诊断开启的内部 A/B，**不可直接与之前 1024-token SSE 的 30.757 /
173.094 tok/s 比较**。未完成关闭诊断的长输出、长上下文和完整故障矩阵，因而没有
将新开关设为默认，也不把本次数字称为生产服务速度。worker 单项约 1% 的收益较小，
未来仍应做交错重复；四组按 baseline→worker→async→combined 顺序执行。

NVFP4 下载及 HF 校验在本轮有效 baseline 加载前完成：校验日志报告 419 个远端文件
checksum 匹配，完成时间为服务器 2026-09-21 02:02:02 +09。后续对照未继续下载。
该 checkpoint 不参与本轮测试，权重仍是原有 W4/W8。

## 正确性与检查

- 原有 C++ runtime tests、66 项 Python 测试通过。
- 新增 CPU worker 测试在 macOS/Linux 通过：10,000 代线程身份与计数、两个方向的
  异常唤醒、非 `std::exception` 异常、重复创建/析构。
- 双 GPU host、同步 P2P、异步 P2P 独立测试通过：延迟 producer、in-place token-major
  gather、BF16 RNE、设备恢复、两个 group、1,024 轮交替 stream 连续提交、较大
  F32/BF16 非整块尾部、collective mismatch 双侧失败。
- 每组 6 个模型 case（web 三轮、thinking、数学、较长输入），每组共生成 1,054 个
  token。四组的 prompt IDs 与完整生成 IDs 相同。
- 每组保留 35 份完整词表 BF16 logits，比较原始字节 SHA256 全部相同；仅排除事务
  epoch 字段，selected token、frontier 等其余记录相同。这不是对每一步都取了 logits。
  140 份文件取回本地后也逐文件比较了原始 bytes，三个候选均与基线完全相同。
- 数学样本实际生成 `391`。本轮是相对原生基线的等价检查，不是新的完整模型质量评估。

首次对照脚本漏传 decode RPC 的 `argument0=1`，只完成 append 后进入恢复流程。
修正脚本后完整重跑；首次失败材料保留为 `baseline-attempt1`，未计入以上成绩。
